# 0065: Publish one complete private file proxy from a common collection

Date: 2026-11-07. State: implementation and native qualification in progress.

A flat common collection retains exact originals and proof; ordinary Go clients
need one native proxy tree. Build that tree from every selected root, while
retaining the original complete journal, checkpoint statement/signature, public
key, common manifest and collection metadata. Authenticate the complete journal
again using an explicitly independently selected key/head. A copied key, boolean
or completion receipt supplies no independent trust.

Require an owner-private source directory and hold its directory lock. Bind its
canonical manifest and every proof/member identity to original creation before
output. Validate the original collection binding/receipt and exact member set;
then physically hash/inspect every copied ZIP/mod/info. Never extract or execute
package contents. Source tokens and client configuration are not retained.

Use an exclusive new private output directory with an immutable intent binding.
Stage all native package paths, selected-version lists/latest information,
original proof and the final receipt under one unpublished tree. Sync every file
and created directory before atomically exposing the complete bundle/proxy path.
A late failure emits no success output and leaves no final servable tree. Retain
uncertain private state for explicit same-input resume; reject unknown files,
links, another selection or changed complete metadata without overwriting them.
A published-tree replay rehashes/reverifies and returns its original receipt.

Keep directory enumeration, path count/depth, metadata, input, copy memory and
time bounded. Original roots remain bounded to256 and common metadata to8MiB.
Use only canonical native coordinates and deterministic selected-root discovery.
Discovery describes this selected set, not the original server's global latest.
A complete tree covers every selected original; it does not prove automatically
selected dependency, permission, provenance or public checksum-authority closure.
Current destination admission/scanning remains separate and false in the receipt.

Require meaningful parser/filesystem regressions, real PostgreSQL/common-set
creation/collection and pinned stock Go inert downloads on actual Linux x86/ARM.
Keep network, VCS and toolchain fallback disabled. Separate actual producer/
consumer host qualification must retain independently selected trust and all
original portability controls. Local stand-ins and tagged compile do not qualify
native clients, PostgreSQL, signer execution or host independence.

The full six-step export plan, all fourteen cases/seven environments and all450
capabilities/41families/later GOAL4.1 remain required. Full dependency selection,
current scanner/import/provenance/operator flow, lifecycle/GC/providers/platforms/
backup/HA/scale/production remain open. No primary, customer, sibling, release,
package or image changes are implied.
