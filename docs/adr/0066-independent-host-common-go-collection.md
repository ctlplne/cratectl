# 0066: Qualify common Go collections on independent native hosts

Date: 2026-11-07. State: implemented and locally checked; native qualification pending.

The original two-job workflow proves a single hosted version across independent
x86 producer and ARM consumer VMs. Preserve all sixteen original stages and their
exact artifact, trust, byte, network and refusal assertions. Extend those same
jobs with a separate common-collection fixture and evidence contract.

The owned producer creates, approves and collects all eight explicitly selected
transitive modules through real PostgreSQL, TLS and an externally signed complete
journal. After the source listener closes, retain only the exact private flat
collection: original manifest, complete journal/checkpoint/public signature/key,
canonical collection binding/receipt and every root's ZIP/mod/info. Refuse private
keys, credentials, configs, caches and logs. Bound the owned fixture to 31 files,
512 KiB per file, 1 MiB decoded total and a 2 MiB JSON capsule. These are declared
small-fixture qualification bounds, not product limits.

Use an exact GitHub artifact ID. Transport the capsule digest, public-key digest
and source-runner fingerprint through separate job outputs. The consumer must
check all three, its candidate/run context and its different actual runner before
using any bytes. A key copied beside a manifest supplies no independent trust.
This is a workflow trust-channel stand-in, not a production signer service.

The consumer builds its own native CLI and SDK. It has no registry or PostgreSQL
service. Reverify the original creation and complete proof, then create one complete
private file proxy and download every inert selected module with pinned Go 1.27.3.
Observe empty network namespaces and the original ordinary UID before each offline
command, with VCS/toolchain/direct-network fallback disabled. Preserve uncertain
acknowledgement/replay and later corruption controls, and explicitly reject changed
manifest, later ZIP, journal/signature/key/set identity, copied claims and unknown
members without publishing a new complete result.

Observe the actual CLI PID before exec inside the verified empty network. Before
SIGKILL, verify its executable inode, ordinary UID, network namespace and bounded
ancestry back to the owned launcher. Signal through a Linux process descriptor so
PID reuse cannot select another process. A launcher's PID alone does not establish
which executable received the signal. Keep PID/proc details private; publish only
the reviewed result and proof hashes. Filesystem stand-ins do not qualify signalling.

Safe evidence retains exact input/code/binary/probe digests, ordered stages and
native runner identity. The read-only campaign verifier must require both original
and common records and pair their actual distinct source/destination runners. No
partial report, copied boolean or skipped stage supplies a pass. Do not push new
workflow/report contracts until the current candidate has been fully retained.

This qualifies only an explicitly selected private graph across two native VMs.
Automatic dependency/permission/provenance/authority selection, current scanning
and destination import, production providers, Windows ACLs, power loss, disconnected
installation, backup/HA/scale and all fourteen export cases/seven environments,
450 capabilities, 41 families and later GOAL 4.1 requirements remain open.

The new four producer/fourteen consumer stages supplement all original sixteen.
They share the original two native jobs and add no new workflow. Shared summary
