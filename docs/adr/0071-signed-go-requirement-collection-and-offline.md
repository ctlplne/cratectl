# 0071: Retain and independently replay every original requirement input

Status: implemented but unverified on native PostgreSQL/SDK hosts. Local ARM
build/unit/race/lint and tagged compilation establish their stated scopes only.
All owner-amended GOAL4.1 requirements, 14 export cases and seven environments
remain required. No migration changes accompany this caller implementation.

The schema-18 parent binds both selected payloads and every examined metadata
input. A selected-root collector cannot authenticate that different creation
event or reproduce the metadata selection from selected payloads alone. Add
explicit requirement collect, verify and offline commands. They first verify the
complete original journal against independently selected tenant/start/head,
creation sequence and external checkpoint public key. The original six-field
production event must bind the exact graph parent; a copied receipt, adjacent
public key or self-reported success flag supplies no authority.

Collection binds a flat immutable map before payload writes: parent, complete
journal/checkpoint/signature/public key, project go.mod, canonical requirement
index, selected-root manifest, each examined source manifest/.mod and every
selected ZIP/mod/info. At most 1,024 examined inputs and 256 selected roots make
2,824 members. Stream count/descriptor checks precede typed JSON allocation.
Bindings and receipts retain the existing 512 KiB metadata bound; legacy
directory/member limits remain unchanged. Whole bytes, serial range requests,
chunk size, time, parser inputs and directory entries remain bounded.

An owner-private directory and OS lock retain pending and complete state. Existing
metadata publication supplies exact-prefix recovery, file/directory sync and
exclusive final links. An incomplete local proof or remote member prefix must
match its original bytes before appending; a corrupt prefix is preserved unchanged.
Range status/length/digest/generation are checked on every response. Final graph
HEAD/status recheck current all-input authority before immutable completion.
Explicit same-input resume retains the first completion generation/bytes after
renewal. Collection sends no automatic remote acknowledgement.

Offline verification reopens the retained whole chain, rechecks the independently
selected signature and real creation, derives the complete expected member map,
hashes all originals and binds each source manifest to the parent. It independently
replays the requirement algorithm from the original project and examined .mods,
then inspects selected original ZIP/mod/info and native h1 values. Offline assembly
reauthenticates these inputs before creating output and uses the existing private
staging/sync/publication/replay machinery with distinct requirement profiles.

A native client may need a lower, unselected .mod to reconstruct minimum version
selection. Project those original metadata bytes into native file-proxy paths too.
Only selected versions receive ZIP/info, version-list and latest discovery.
Unselected metadata never creates an unavailable package advertisement. The bundle
also retains every original proof member separately for independent inspection.

The new native case belongs in the existing Linux x86/ARM PostgreSQL suites,
normally and under race. It creates a mixed modern/legacy three-input competing
version graph with two selected roots, signs the real journal using external
OpenSSL, collects through trusted TLS with the actual candidate CLI, and checks
current source denial without rewriting historical completion. After stopping
the source listener, observed empty command networks contain actual CLI
verification/assembly/refusal/replay and pinned stock Go metadata/download commands.
They must demonstrate the SDK actually reads the unselected original .mod, chooses
the same versions and extracts the exact inert bytes with matching native hashes.
Wrong key/head/event, insufficient budget, corrupt original and unknown member
must refuse without success output or repair of retained state.

A subsequent recovery extension adds an inert padding member while preserving
the selected module's original go.mod and asset. The real second64KiB ZIP range
provides a socket barrier for killing/reaping only the spawned candidate CLI.
The native test must retain exactly the synced first range and no completion,
renew the real session, reject stale generation and unchanged corrupt prefix,
then complete valid generation2 bytes. Another renewal to3 must replay the exact
original generation2 receipt. The later source-denial control uses current3 so
it cannot pass through an unrelated stale-generation rejection. These recovery
assertions pass local fixture/unit/race checks and tagged compilation only; the
older f320 normal/race native proof does not contain them. See the
[recovery development record](../../evidence/2026-11-07/go-requirement-recovery-development.json).

This is a metadata-selection and original-byte proof. Dependency/package/platform
closure, checksum authority, current source/destination admission, import/scanning,
workspace/replacement/exclusion/source-precedence breadth, independent-host
requirement-profile transfer, native qualification of interruption/renewal for this profile,
Windows/providers/installation/GC/backup/HA/scale and full product scope remain
unfinished. Existing explicit-set independent-host/process proofs retain their
own scope and do not automatically qualify this new profile.
